# 组员 B 本地实验结果完整分析

## 0. 分析对象与结论概览

本分析综合当前三个来源：

- 评估程序：`src/evaluation/evaluate_outputs.py`
- controlled 汇总程序：`scripts/summarize_member_b_controlled.py`
- 实验输出：`outputs/controlled/`、`outputs/rgb_results/`、`outputs/ramdocs_results/`

当前 controlled 本地实验已经覆盖计划矩阵：

| 项目 | 数量 |
|---|---:|
| controlled 设置 | 15 |
| 方法数 | 6 |
| 输出文件 | 90 |
| 输出记录 | 28,980 |
| missing output | 0 |
| `DataInspectionFailed` 等模型服务拦截 | 13 |

本地 controlled 实验主要用于分析“噪音比例”和“正确文档位置”两个因素。运行时使用 `--disable-neural`，因此检索和重排采用词法 fallback，它更适合做机制诊断，不应完全替代正式神经检索版本的主结果。

总体结论：

1. 正确文档位置确实会影响回答，但这种影响主要出现在 `ordered_rag` 这种按输入顺序截断上下文的方法中。
2. 一旦方法具备检索、重排或证据筛选，RGB 60% 噪音下的前、中、后、随机位置差异明显缩小。
3. 普通 noise 与 misinformation 的影响不同。RGB 普通噪音在 0%-80% 范围内不一定造成单调下降，但 RAMDocs 的误导文档会显著提高错误答案采纳率。
4. 100% 噪音是最强压力测试。所有 RAG 方法在 100% 噪音下 Accuracy 接近崩溃，且拒答能力不足。
5. 当前结果支持 EGI-RAG 中“文档评分、证据抽取、答案校验、迭代修正”的必要性，但正式实验前必须注意 prompt 标签泄露和自动评估指标偏粗的问题。

## 1. 评估程序口径

`evaluate_outputs.py` 对每条样本按 `id` 对齐 input、reference 和 output，并计算以下指标：

| 指标 | 程序定义 | 使用风险 |
|---|---|---|
| Accuracy | 模型答案中是否包含任一 gold answer | 字符串包含匹配，可能低估同义表达、翻译表达和格式变化 |
| Exact Match | 标准化后是否与 gold answer 完全一致 | 对短答案严格，对自然语言答案偏苛刻 |
| F1 | prediction 与 gold answer 的 token 级重叠 | 中文答案分词不充分，数值只作参考 |
| Misinfo Adoption | 模型答案中是否包含 `wrong_answers` | 只能评估 RAMDocs 等有 wrong answer 的样本 |
| Evidence Acc | `selected_doc_ids` 是否命中 correct 文档 | 只判断选中文档，不判断答案是否真正忠实 |
| Refusal Acc | 无正确文档时应拒答，有正确文档时不应拒答 | 适合 100% 噪音压力测试 |
| Faithfulness | 有 `verification_result=supported`、`evidence_spans` 或选中 correct 文档即算 faithful | 是代理指标，不是真正的语义忠实性判断 |

因此，当前指标适合做大规模趋势分析，但最终报告中应明确说明：Accuracy、Misinfo Adoption 和 Evidence Acc 是自动评估指标，典型案例仍需人工核验或 LLM judge 复核。

## 2. 噪音数据构造分析

controlled 数据由 `build_controlled_noise_sets.py` 构造，核心逻辑如下：

- 将每条样本的文档分为 `correct_docs` 和 `noise_docs`。
- `noise_docs` 包含 `noise`、`misinfo`、`contradictory`、`unknown`。
- 每条最多保留 10 篇文档。
- 名义噪音比例为 `0%/20%/40%/60%/80%/100%`。
- 正确文档位置为 `front/middle/back/random`。

RGB 的实际比例控制较准：

| 名义比例 | 实际平均噪音比例 |
|---:|---:|
| 0% | 0.0% |
| 20% | 23.7% |
| 40% | 41.5% |
| 60% | 60.0% |
| 80% | 79.9% |
| 100% | 100.0% |

RAMDocs 受原始样本中可用噪音文档数量限制，名义比例和实际比例有差距：

| 名义比例 | 实际平均噪音比例 |
|---:|---:|
| 20% | 27.3% |
| 60% | 46.1% |
| 100% | 100.0% |

这个构造对题目有帮助，因为它把“文档位置”和“噪音比例”拆开做了可控变量。但它也有局限：当前噪音主要来自原始数据集已有文档，不是新合成的“相关但缺少逻辑依赖”的文档。若最终报告要更贴近题目描述，应补充少量自定义逻辑缺失噪音。

## 3. 正式神经版主实验结果

正式神经版实验使用 `bge-m3 + FAISS` 检索和 `bge-reranker-v2-m3` 重排，是主结果中更适合作为 baseline 性能对比的一组。

### 3.1 RGB 主结果

| 方法 | Accuracy | Refusal |
|---|---:|---:|
| Zero-shot | 27/300 = 9.0% | 104 |
| Naive RAG | 208/300 = 69.3% | 1 |
| Rerank RAG | 209/300 = 69.7% | 0 |
| CRAG-lite | 208/300 = 69.3% | 3 |
| Self-RAG-lite | 212/300 = 70.7% | 2 |

RGB 证据选择：

| 方法 | selected correct | selected noise | contains correct |
|---|---:|---:|---:|
| Naive RAG | 1227 | 273 | 299/300 = 99.7% |
| Rerank RAG | 1384 | 116 | 299/300 = 99.7% |
| CRAG-lite | 1354 | 33 | 296/300 = 98.7% |
| Self-RAG-lite | 1384 | 116 | 299/300 = 99.7% |

分析：

- Zero-shot 只有 9.0%，说明 RGB 任务强依赖上下文文档。
- RAG 系列提升到约 69%-71%，证明引入检索文档对问答有效。
- Rerank 将 selected noise 从 273 降到 116，说明重排对普通噪音有明显过滤作用。
- CRAG-lite 将 selected noise 进一步降到 33，但 Accuracy 没有提升，说明过滤更强不等于最终答案更准，可能损失部分弱证据或增加保守性。
- Self-RAG-lite 最高，为 70.7%，说明生成后自检在 RGB 上有小幅正收益。

### 3.2 RAMDocs 主结果

| 方法 | Accuracy | Refusal | Wrong adoption |
|---|---:|---:|---:|
| Zero-shot | 34/500 = 6.8% | 317 | 3/306 = 1.0% |
| Naive RAG | 320/500 = 64.0% | 293 | 88/306 = 28.8% |
| Rerank RAG | 317/500 = 63.4% | 297 | 103/306 = 33.7% |
| CRAG-lite | 311/500 = 62.2% | 198 | 36/306 = 11.8% |
| Self-RAG-lite | 183/500 = 36.6% | 285 | 37/306 = 12.1% |

RAMDocs 证据选择：

| 方法 | selected correct | selected noise | selected misinfo | contains correct | contains misinfo |
|---|---:|---:|---:|---:|---:|
| Naive RAG | 1586 | 320 | 271 | 497/500 = 99.4% | 228/500 = 45.6% |
| Rerank RAG | 1604 | 308 | 265 | 497/500 = 99.4% | 221/500 = 44.2% |
| CRAG-lite | 1034 | 48 | 30 | 453/500 = 90.6% | 27/500 = 5.4% |
| Self-RAG-lite | 1604 | 308 | 265 | 497/500 = 99.4% | 221/500 = 44.2% |

分析：

- RAMDocs 揭示的不是普通噪音问题，而是 misinformation 风险。
- Naive RAG 和 Rerank RAG 都能显著提高 Accuracy，但 wrong adoption 很高。
- Rerank 的 wrong adoption 从 Naive 的 28.8% 上升到 33.7%，说明重排器更偏向相关性，而误导文档往往也高度相关。
- CRAG-lite 的 Accuracy 略低，但 wrong adoption 降到 11.8%，selected misinfo 从 271/265 降到 30，证明生成前证据门控有效。
- Self-RAG-lite 能降低 wrong adoption，但 Accuracy 只有 36.6%，说明当前自检和重写策略过于保守。

## 4. 正确文档位置影响

位置实验最关键的是 RGB 60% 噪音。`ordered_rag` 按输入顺序取前 5 篇文档，因此最能暴露位置敏感性。

| 方法 | front | middle | back | random |
|---|---:|---:|---:|---:|
| zero_shot | 0.1067 | 0.1067 | 0.1200 | 0.1067 |
| ordered_rag | 0.7367 | 0.7233 | 0.0633 | 0.7133 |
| naive_rag | 0.7467 | 0.7367 | 0.7333 | 0.7400 |
| rerank_rag | 0.7367 | 0.7433 | 0.7300 | 0.7300 |
| crag_lite | 0.6867 | 0.7200 | 0.7167 | 0.7100 |
| self_rag_lite | 0.7467 | 0.7333 | 0.7300 | 0.7267 |

结论：

- `ordered_rag` 从 front 的 0.7367 跌到 back 的 0.0633，说明只依赖输入顺序截断会被正确文档位置严重影响。
- `naive_rag`、`rerank_rag` 和 `self_rag_lite` 在四种位置下都较稳定，说明检索能缓解原始上下文顺序偏置。
- 因此，报告中不应写成“所有 RAG 都害怕正确文档后置”，更准确的说法是：不做检索或证据选择的顺序拼接方法对位置高度敏感，而检索式 RAG 能显著降低这种敏感性。

对 EGI-RAG 的启发：

- 必须保留文档级评分或证据级抽取，不能直接按检索输入顺序拼接上下文。
- 需要关注 top-k 截断边界。如果正确文档被噪音挤到 top-k 之外，生成器就完全看不到证据。
- 案例分析可优先选择 `ordered_rag_rgb_noise060_back_output.json`，展示“正确文档在后导致模型无证据或错误回答”的失败模式。

## 5. 噪音比例影响

RGB front 设置下的 Accuracy：

| 方法 | 0% | 20% | 40% | 60% | 80% | 100% | 0% 到 80% 变化 | 0% 到 100% 下降 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| zero_shot | 0.1100 | 0.1033 | 0.1067 | 0.1067 | 0.1033 | 0.1033 | -0.0067 | 0.0067 |
| ordered_rag | 0.7233 | 0.7367 | 0.7200 | 0.7367 | 0.7300 | 0.0600 | +0.0067 | 0.6633 |
| naive_rag | 0.7033 | 0.7200 | 0.7333 | 0.7467 | 0.6833 | 0.0533 | -0.0200 | 0.6500 |
| rerank_rag | 0.7267 | 0.7167 | 0.7300 | 0.7367 | 0.6967 | 0.0567 | -0.0300 | 0.6700 |
| crag_lite | 0.7067 | 0.7167 | 0.7200 | 0.6867 | 0.7000 | 0.0400 | -0.0067 | 0.6667 |
| self_rag_lite | 0.7067 | 0.7333 | 0.7267 | 0.7467 | 0.6767 | 0.0533 | -0.0300 | 0.6534 |

结论：

- 0%-80% 普通噪音下，RGB Accuracy 没有明显单调下降，说明只要正确证据仍在候选池中，当前方法能较好恢复答案。
- 100% 噪音下，所有 RAG 方法跌到 0.04-0.06 左右，说明没有正确证据时模型仍倾向于被上下文牵引。
- Zero-shot 不读取上下文，因此基本不受噪音比例影响，但整体 Accuracy 只有 0.10 左右，不具备实用性。
- 100% 噪音时 Zero-shot 反而高于 RAG，这说明错误上下文可能比没有上下文更危险。

改进方向：

- 对 100% 噪音或无有效证据场景，方法应触发拒答，而不是继续生成实体或日期。
- 报告中可增加 Noise Sensitivity Drop：`Accuracy(0%) - Accuracy(100%)`。当前 RAG 方法下降约 0.65-0.67，是非常直观的鲁棒性指标。

## 6. RAMDocs 误导文档影响

RAMDocs front 设置下的 Accuracy 与 Misinfo Adoption：

| 方法 | 20% Acc | 60% Acc | 100% Acc | 20% Misinfo | 60% Misinfo | 100% Misinfo |
|---|---:|---:|---:|---:|---:|---:|
| zero_shot | 0.0685 | 0.0709 | 0.0655 | 0.0024 | 0.0049 | 0.0049 |
| ordered_rag | 0.6797 | 0.6137 | 0.0121 | 0.1174 | 0.1834 | 0.2524 |
| naive_rag | 0.6626 | 0.6137 | 0.0146 | 0.1711 | 0.1980 | 0.2743 |
| rerank_rag | 0.6528 | 0.6064 | 0.0097 | 0.1663 | 0.1907 | 0.2743 |
| crag_lite | 0.6235 | 0.5746 | 0.0073 | 0.0513 | 0.0807 | 0.2184 |
| self_rag_lite | 0.3790 | 0.3985 | 0.0073 | 0.0562 | 0.0807 | 0.2233 |

结论：

- 从 20% 到 60%，Naive RAG Accuracy 从 0.6626 降到 0.6137，Misinfo Adoption 从 0.1711 升到 0.1980。
- Rerank RAG 不能根治误导文档，100% 噪音下误导采纳率仍为 0.2743。
- CRAG-lite 明显降低误导采纳率：20% 时从 Naive 的 0.1711 降到 0.0513，60% 时从 0.1980 降到 0.0807。
- Self-RAG-lite 同样降低误导采纳，但 Accuracy 大幅偏低，说明生成后自检在当前 prompt 下过于保守。

对方法设计的启发：

- 文档选择不能只优化相关性，因为 misinfo 往往也与问题高度相关。
- Document Scorer 需要显式区分 `directly_supportive`、`misleading` 和 `insufficient`。
- Evidence Extractor 应只抽取能够直接支持答案的句子。
- Verifier 应检查答案中的实体、数值、日期是否逐项被证据支持。

## 7. 方法对比与定位

| 方法 | 当前表现 | 适合承担的实验角色 |
|---|---|---|
| Zero-shot | 准确率低，但不受上下文噪音影响 | 无上下文下限 |
| Ordered RAG | 位置敏感性极强，back 位置崩溃 | 位置影响诊断方法 |
| Naive RAG | 正确证据存在时强，误导文档多时不安全 | 基础 RAG baseline |
| Rerank RAG | 能改善普通噪音选择，但不能判断真伪 | 强相关性 baseline |
| CRAG-lite | 明显降低 misinfo adoption，但可能牺牲部分准确率 | 生成前证据门控对比 |
| Self-RAG-lite | 能降低误导采纳，但在 RAMDocs 上过度保守 | 生成后自检对比 |
| EGI-RAG | 尚需接入同一评估脚本 | 最终方法，应组合证据门控与生成后校验 |

建议最终报告中的方法叙事：

1. Zero-shot 证明任务需要外部上下文。
2. Ordered RAG 证明好文档位置会影响顺序拼接式 RAG。
3. Naive/Rerank 证明检索和重排能缓解普通噪音，但不能解决误导文档。
4. CRAG/Self-RAG 证明证据门控和自检有效，但单独使用存在缺陷。
5. EGI-RAG 的价值应表述为：同时降低错误文档进入生成器的概率，并在生成后校验答案是否被证据支持。

## 9. 当前结果的主要风险

### 9.1 Prompt 标签泄露

当前 prompt 格式中会输出 `label=correct/noise/misinfo`。这对调试方便，但正式实验存在标签泄露风险。模型可能根据标签作答，而不是根据文档内容判断证据可靠性。

建议：

- 正式实验 prompt 中删除 `label=` 字段。
- 评估脚本继续保留标签用于计算 Evidence Acc、Misinfo Adoption。
- 如果时间不足，报告中必须说明 controlled 本地实验属于诊断实验，标签用于分析和调试，不作为最终公平对比。

### 9.2 本地 controlled 使用词法 fallback

本地 controlled 运行用了 `--disable-neural`，因此不能直接代表 `bge-m3 + bge-reranker` 的最终性能。它的价值主要是可快速复现变量趋势。

建议：

- 主性能表引用正式神经版 RGB/RAMDocs 全量结果。
- 位置和噪音比例消融引用本地 controlled 结果。
- 报告中明确区分“主实验”和“controlled 消融实验”。

### 9.3 自动指标偏粗

Accuracy 是字符串包含匹配，Faithfulness 是代理指标。复杂答案、中文翻译、简称、日期格式可能被误判。

建议：

- 每类关键结论补 1-2 个案例。
- 对最终 EGI-RAG 与最强 baseline 的对比，抽样人工复核。

## 10. 建议补充的自定义噪音

不必再跑完整矩阵，可以小规模补 30-50 条：

| 噪音类型 | 构造方式 | 目的 |
|---|---|---|
| 高词面重叠无关噪音 | 保留问题关键词，但删除答案事实 | 测试关键词检索是否被欺骗 |
| 逻辑缺失噪音 | 文档提到实体和背景，但缺少回答所需的关键关系 | 对齐题目“相关但缺少逻辑依赖”的定义 |
| 数值替换误导噪音 | 保留实体，替换日期、人口、地点、奖项等细节 | 测试模型是否采纳错误细节 |
| 冲突噪音 | 构造与 correct 文档相反的事实陈述 | 测试冲突证据处理能力 |
| 位置对抗噪音 | 将 correct 文档固定放在 top-k 之外 | 测试截断边界和重检索机制 |

推荐组合：

- 数据：RGB 60%、RGB 100%、RAMDocs 60%、RAMDocs 100%
- 方法：Naive RAG、Rerank RAG、CRAG-lite、EGI-RAG
- 样本：每档 30 条即可，用于案例分析和补充表格

## 11. 最终报告可用结论

可以将结论写成：

> 实验表明，RAG 系统对噪音文档的鲁棒性取决于噪音类型和证据选择机制。对于普通无关噪音，检索和重排能够在正确证据仍存在时维持较高准确率；但当正确文档被放到顺序截断范围之外时，按顺序拼接的 Ordered RAG 准确率从 0.7367 降至 0.0633，说明正确文档位置会显著影响未检索或弱检索方法。对于 RAMDocs 中的 misinformation，单纯重排并不能降低错误答案采纳率，Naive RAG 和 Rerank RAG 在 100% 噪音下的误导采纳率均达到 0.2743。CRAG-lite 能将 60% 噪音下的误导采纳率从 Naive RAG 的 0.1980 降到 0.0807，证明生成前证据门控有效；但其准确率略有下降，Self-RAG-lite 也存在过度保守问题。因此，最终方法应同时包含文档评分、证据抽取、答案一致性校验和必要时的迭代修正，以在保留正确答案能力的同时降低误导文档采纳。

## 13. 与题目要求的逐条对应

## 14. 对助教意见的直接回答

助教意见可以概括为四句：看好文档位置影响、看噪音文档影响、给出建设性方法实验意见、允许自己设置噪音。基于当前结果，可以直接回答为：

| 助教意见 | 是否完成 | 当前可以怎么说 |
|---|---|---|
| 好的文档的位置产生的影响 | 已基本完成 | `ordered_rag` 在 RGB 60% 噪音下从 `front=0.7367` 跌到 `back=0.0633`，位置影响非常显著；而检索式 RAG 方法位置敏感性明显下降 |
| 噪音文档产生的影响 | 已完成主要趋势 | RGB 显示普通 noise 对结果有扰动但不一定单调破坏；RAMDocs 显示 misinfo 会明显提高错误答案采纳率；100% 噪音会让所有 RAG 接近崩溃 |
| 方法实验结果建设性意见 | 已完成 baseline 建议，最终方法建议部分完成 | 已能明确提出“仅相关性排序不够，需要证据门控 + 生成后校验”；但 EGI-RAG full 结果还需补齐 |
| 可以自己设置噪音 | 已部分完成 | 已实现比例可控、位置可控的噪音构造；但尚未补充“相关但缺少逻辑依赖”的自定义逻辑噪音 |

因此，最准确的总体判断是：

1. 当前实验**对题目目标是有帮助的**，而且帮助很直接，因为它已经把“位置影响”和“噪音比例/类型影响”从泛泛讨论变成了可复现的消融实验。
2. 当前实验**已经完成助教意见中的大部分分析要求**，尤其是位置影响、噪音影响和 baseline 方法比较。
3. 当前实验**还没有完全闭环**，因为最终矫正方法 EGI-RAG 的正式结果、矫正前后案例、以及“逻辑依赖缺失型噪音”的自定义构造还需要补。

## 15. 最终总判断

如果现在就写阶段性结论，建议使用下面这段：

> 目前项目已经完成了题目要求中的核心分析框架。我们基于统一评估程序和 controlled 实验集，系统分析了正确文档位置、噪音比例以及 misinformation 对 RAG 问答性能的影响。结果表明：顺序拼接式方法对好文档位置高度敏感，而检索与重排可以明显降低这种敏感性；普通 noise 会带来性能波动，但 misinformation 会显著提高错误答案采纳率，说明仅依赖相关性排序不足以保证鲁棒性。CRAG-lite 和 Self-RAG-lite 进一步证明了生成前证据门控和生成后自检的价值，因此 EGI-RAG 这类“证据门控 + 一致性校验 + 迭代修正”的方法设计是有实验依据的。当前尚需补充 EGI-RAG 正式结果、矫正前后案例，以及少量自定义逻辑缺失噪音实验，才能完全覆盖题目要求和助教建议。
